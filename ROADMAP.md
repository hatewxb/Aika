## Как работать (кратко)

- Steam запущен с `-dev`, CDP на `http://localhost:8080/json`. Главное окно —
  страница с заголовком «Steam». Меню — отдельные окна («Games Root Menu»,
  «Menu», «… Supernav»).
- Классы снимать самому через CDP (Runtime.evaluate, CSS.getMatchedStylesForNode):
  смотреть и читаемый класс, и силу (специфичность) правила Steam, которое
  надо перебить. Скрипты в `tools/` (Node, без зависимостей; без аргумента
  окна работают с главным окном «Steam»):
  - `node tools/cdp.js "<выражение>"` — выполнить JS в окне;
    окно можно указать частью заголовка: веб-страница сообщества
    «Сообщество Steam :: … :: Активность друзей» — это
    `node tools/cdp.js "Активность друзей" "…"`, перезагрузка её CSS —
    `node tools/reload.js "Активность друзей" webkit.css`;
  - `node tools/rules.js "<селектор>" "background,color"` — какие правила
    Steam задают свойства (от сильного к слабому);
  - `node tools/reload.js` — перезагрузить CSS темы без перезапуска Steam
    (`node tools/reload.js "Games Root Menu" popup.css` — в окне-меню);
  - `node tools/hover.js "<селектор>"` — навести мышь на элемент (прокрутит к нему),
    затем audit.js видит :hover-цвета; `node tools/hover.js off` — убрать мышь;
  - открыть страницу игры: `Start-Process "steam://nav/games/details/<appid>"`
    (PowerShell); appid — через окно SharedJSContext:
    `collectionStore.allAppsCollection.allApps` (appid, display_name);
  - `node tools/audit.js Steam all "<область>"` — найти видимые элементы
    в цветах Steam (не из палитры Aika) и плашки без скругления. Видит
    только то, что в окне: для длинных страниц прокрутить (scrollTop
    через cdp.js) и запустить ещё раз. Подождать ~3 с после reload —
    иначе ловит CSS-переходы Steam. **Каждый новый раздел закрывать
    чистым аудитом** (кроме намеренных исключений ниже).
- Скриншоты через CDP в Steam не работают — визуальную проверку просить
  у автора. Значения проверять по computed-стилям; при чтении сразу после
  перезагрузки CSS дождаться окончания transition (~0.5 с).
- Перебивать Steam без `!important`: префикс `html`, тег, ещё один читаемый
  класс. `!important` — только если у Steam он сам стоит (комментарий рядом).
- Хэш-классы (`_1UBp…`) — только в `selectors.css` с датой проверки.
  Часто у хэша есть читаемый двойник (`Selected`, `HoversEnabled`, `Play`) —
  проверять в живом состоянии (выбрать игру, навести мышь) прежде чем
  уходить в selectors.css.
- Цвета: `root-colors.css` (RootColors, только #hex) / `colors.css` (всё
  остальное). Никаких `rgba()` в root-colors.css — Millennium обнуляет альфу.
- Новые Patches в skin.json подхватываются только после перезапуска Steam.
- Коммит после каждого законченного шага; в конце шага — коротко автору:
  что сделано, хэш, что проверить в Steam.

## Известные ограничения

- У Fraunces нет кириллицы — русские крупные заголовки уходят в Georgia.
- Вкладки различаются по позиции (`nth-of-type`), т.к. своих классов нет;
  «Консоль» есть только в режиме `-dev`.
- Фон тела блоков страницы игры — `!important` (у Steam там тоже).
- Полки домашней страницы не bento: сетка Steam сама считает позиции,
  перестройка ломает прокрутку и перетаскивание.

- Правая колонка страницы игры у Steam — float: right; блоки левой колонки
  держим flow-root (иначе они либо уезжают под колонку, либо тянут тёмное
  тело под неё). Не ставить им width: 100%.

### Намеренные исключения аудита (не чинить)

- Золото редких достижений (`RareAchievementIconGlow`, `IconGlow`) — знак редкости.
- Золотой / красный / бронзовый онлайн «PLAYERS» — inline-стиль стороннего плагина Millennium.
- Панели во всю высоту окна — вровень с краями, без скругления.
- Красный/золотой онлайн в «Играть» — inline-стиль плагина (см. выше).
- Подпись к скриншоту в ленте (`ScreenshotCaption`) — скруглён только
  верхний правый угол: она прижата к краю картинки.
- 3D-грани куба в блоке предзаказа (`CubeFace`).
